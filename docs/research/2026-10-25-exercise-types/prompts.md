## P1. Политика выбора упражнений + «der / die / das» (A1) — приоритет: высокий, S

```text
Задача: добавить упражнение «der / die / das» и правило, по которому из всех возможных упражнений
для абзаца выбираются показанные.

Контекст: сейчас apps/cms/src/exercises/generate.ts детерминированно строит ≤4 упражнения
(word-pairing, fill-blank, multiple-choice, audio-dictation) из markedVocab. Лимит .max(4) стоит в
ExercisesResponseSchema (packages/shared/src/schemas/cms.ts) и в ExerciseSetSchema (storage.ts).
Глоссы содержат lemma с артиклем для существительных ("das Riesenrad", "die Leute").

Сделай:
1. Новый kind "article-choice": для существительного из markedVocab с леммой, начинающейся с
   der/die/das, показать слово без артикля и три кнопки der/die/das. Мн.ч.-only («die Leute»)
   пропускать, если нельзя отличить от женского рода. Неоднозначные леммы (без артикля, «der/das»)
   пропускать.
2. Пройди всю цепочку: CmsExerciseSchema + ExerciseKindSchema + ExerciseSchema в shared; генерация в
   apps/cms/src/exercises/generate.ts; маппинг в apps/extension/lib/exercises/generate.ts; проверка
   в lib/exercises/match.ts; ArticleChoiceCard.tsx в entrypoints/content/overlay + ветка в Panel.tsx
   (стиль как у MultipleChoiceCard, токены из styles.ts). affectedVocabIds — vocabId леммы.
3. Политика выбора: генератор строит всех кандидатов, затем детерминированно (по хешу текста, как
   уже сделано для вариантов) выбирает не больше N=5 штук: не больше одного упражнения каждого kind,
   не больше двух упражнений на одно слово, word-pairing — если есть ≥2 слова. Подними max в обеих
   схемах до 6 (только повышение — старый кэш IndexedDB продолжит парситься; добавь тест, что набор
   из 4 старых упражнений валиден).
4. Тесты: схемы, генерация (артикль корректно извлекается, мн.ч. и неоднозначные пропускаются,
   политика не превышает N и детерминирована), match, Playwright-сценарий в exercise-panel.spec.ts
   с обновлённым mock CMS.

Вне задачи: изменения промпта перевода, новые разрешения, грамматические темы.
```

## P3. «Собери предложение» (A3) — приоритет: средний, S–M

```text
Задача: упражнение на порядок слов (Satzbau) — главная грамматическая тема немецкого после артиклей.

1. kind "word-order": взять предложение абзаца из 4–9 слов, разбить на токены (знаки препинания
   приклеены к предыдущему токену, финальная точка — фиксированная), перемешать детерминированно
   (хеш, не Math.random) так, чтобы порядок отличался от исходного. Ответ — кнопки-токены, клик
   переносит токен в строку ответа, клик по токену в строке — возвращает.
2. Проверка: точное совпадение с исходным порядком после нормализации пробелов и регистра первого
   слова. Немецкий допускает перестановку членов предложения перед глаголом, поэтому НЕ брать
   предложения, которые начинаются не с подлежащего — эвристика: первое слово — артикль/местоимение
   (ich, du, er, sie, es, wir, ihr, der, die, das, ein, eine…) или имя собственное (заглавная буква
   не в начале не считается). Опиши эвристику в комментарии и покрой тестами.
3. Ответ передавать строкой (токены через пробел) — AnswerPayloadSchema менять не нужно; если
   решишь иначе — обоснуй.
4. Карточка должна работать с клавиатуры (Tab/Enter) — это панель в Shadow DOM, фокус не должен
   уходить на хост-страницу.
5. Тесты: токенизация (пунктуация, умлауты, отделяемые приставки остаются отдельными токенами),
   детерминированность перемешивания, фильтр предложений, match, Playwright.

Вне задачи: разметка членов предложения через LLM (возможный следующий шаг — упомяни в отчёте,
если эвристика отбрасывает слишком много предложений на фикстурах quality-paragraphs).
```


```text
Задача: инструмент «Объяснить» в side panel: перевод фрагмента на русский, пословный разбор и 1–3

Качество: добавь в apps/cms/scripts режим quality-check/judge для explain на 20 немецких

Вне задачи: чат, упражнения по грамматике (P8).
```
